## Скрипты для работы с инфоблоками Bitrix

Этот раздел описывает вспомогательные PHP-скрипты, используемые для экспорта данных и переноса элементов между инфоблоками в CMS Bitrix. Скрипты предназначены для автоматизации задач миграции и обработки данных в проектах на платформе Bitrix.

### Файлы

#### 1. `export_elements_to_csv.php`

**Описание**: Скрипт экспортирует данные из инфоблока Bitrix в CSV-файл, содержащий названия элементов и связанные с ними города.

**Функциональность**:
- Подключает модули `main` и `iblock` для работы с инфоблоками.
- Выбирает активные элементы из заданного инфоблока и раздела:
  - `IBLOCK_ID`: ID инфоблока (по умолчанию 8, требует настройки).
  - `SECTION_ID`: ID раздела (по умолчанию 1743, требует настройки).
  - Включает подразделы и выбирает поля: `ID`, `NAME`, `PROPERTY_CITY` (свойство с ID городов).
- Создаёт CSV-файл (`export_data.csv`) с заголовками: "Название" и "Города".
- Для каждого элемента:
  - Извлекает название (`NAME`).
  - Получает ID городов из свойства `PROPERTY_CITY_VALUE` (может быть одно или несколько значений).
  - Запрашивает названия городов по их ID из инфоблока и объединяет их в строку через запятую.
  - Записывает данные в CSV-файл.
- Отправляет файл пользователю для скачивания и завершает выполнение.

**Назначение**: Используется для выгрузки данных об элементах инфоблока (например, статей, услуг, объектов) и их географической привязки (списка городов) в CSV-формат для анализа, миграции или интеграции с другими системами.

**Пример использования**:
- Выгрузка списка объектов с указанием городов для передачи в другую систему.
- Подготовка отчёта о географическом распределении элементов.

#### 2. `batch_transfer_elements.php`

**Описание**: Скрипт массово переносит элементы из одного инфоблока в другой с сохранением их полей, свойств и изображений, с ограничением на количество обрабатываемых элементов за один запуск.

**Функциональность**:
- Подключает модули Bitrix и использует пространство имён `Bitrix\Iblock\ElementTable`.
- Задаёт параметры:
  - `iblockFromId`: ID исходного инфоблока (по умолчанию 17).
  - `iblockToId`: ID целевого инфоблока (по умолчанию 24).
  - `sectionId`: ID раздела исходного инфоблока (по умолчанию 165).
  - `limit`: Максимальное количество элементов для переноса за раз (по умолчанию 5).
- Выбирает активные элементы из исходного инфоблока, включая поля: `ID`, `NAME`, `DETAIL_TEXT`, `PREVIEW_TEXT`, `DETAIL_PICTURE`, `PREVIEW_PICTURE`, `ACTIVE_FROM`, и все свойства (`PROPERTY_*`).
- Для каждого элемента (в пределах лимита):
  - Формирует массив полей для нового элемента:
    - Копирует название, текст анонса, детальный текст, дату активности.
    - Генерирует символьный код (`CODE`) через транслитерацию названия.
    - Копирует изображения анонса и детальной страницы с помощью `CFile::MakeFileArray`.
  - Переносит свойства элемента, сохраняя их коды и значения.
  - Создаёт новый элемент в целевом инфоблоке через `CIBlockElement::Add`.
  - Выводит сообщение об успехе или ошибке для каждого элемента.
- Выводит общее количество перенесённых элементов.

**Назначение**: Используется для пакетной миграции данных между инфоблоками, например, при реорганизации структуры сайта (перенос новостей, статей, товаров в новый инфоблок). Ограничение по количеству элементов снижает нагрузку на сервер.

**Пример использования**:
- Перенос всех новостей из старого инфоблока в новый с сохранением метаданных.
- Миграция элементов каталога в инфоблок с обновлённой структурой.

**Рекомендации по настройке**:
- Настройте `iblockFromId`, `iblockToId` и `sectionId` под ваш проект.
- Убедитесь, что коды свойств в целевом инфоблоке совпадают с исходным.
- Для обработки большого числа элементов увеличьте `limit` или запускайте скрипт многократно.

#### 3. `single_element_transfer.php`

**Описание**: Скрипт переносит один конкретный элемент из одного инфоблока в другой с сохранением его полей, свойств и изображений.

**Функциональность**:
- Подключает модули Bitrix и использует пространство имён `Bitrix\Iblock`.
- Задаёт параметры:
  - `iblockFromId`: ID исходного инфоблока (по умолчанию 17, новости).
  - `iblockToId`: ID целевого инфоблока (по умолчанию 24, акции).
  - `elementId`: ID элемента для переноса (по умолчанию 1401).
- Выбирает активный элемент по его ID из исходного инфоблока, включая поля: `ID`, `NAME`, `DETAIL_TEXT`, `PREVIEW_TEXT`, `DETAIL_PICTURE`, `PREVIEW_PICTURE`, `ACTIVE_FROM`, и все свойства (`PROPERTY_*`).
- Если элемент найден:
  - Формирует массив полей для нового элемента:
    - Копирует название, текст анонса, детальный текст, дату активности.
    - Генерирует символьный код (`CODE`) через транслитерацию названия.
    - Копирует изображения анонса и детальной страницы с помощью `CFile::MakeFileArray`.
  - Переносит свойства элемента, сохраняя их коды и значения.
  - Создаёт новый элемент в целевом инфоблоке через `CIBlockElement::Add`.
  - Выводит сообщение об успехе или ошибке.
- Если элемент не найден, выводит сообщение об ошибке.

**Назначение**: Используется для выборочного переноса одного элемента, например, перемещения конкретной новости в инфоблок акций с сохранением всех данных.

**Пример использования**:
- Перенос одной важной новости в раздел акций для рекламной кампании.
- Тестирование миграции данных на одном элементе перед массовым переносом.

**Рекомендации по настройке**:
- Укажите актуальные `iblockFromId`, `iblockToId` и `elementId`.
- Проверьте соответствие кодов свойств в исходном и целевом инфоблоках.
- Добавьте логирование ошибок для диагностики.

### Зависимости

- **Модули Bitrix**:
  - `main`: Для базовой функциональности Bitrix.
  - `iblock`: Для работы с инфоблоками и элементами.

### Примечания

- Скрипты предполагают, что пользователь имеет права доступа к инфоблокам и файлам (для работы с изображениями).
- Для массового переноса (`batch_transfer_elements.php`) рекомендуется запускать скрипт в несколько итераций, если элементов много, чтобы избежать перегрузки сервера.
- Экспорт в CSV (`export_elements_to_csv.php`) требует корректной настройки свойства `PROPERTY_CITY` как связи с элементами инфоблока городов.
- Все скрипты используют жёстко закодированные ID (инфоблоков, разделов, элементов), которые нужно адаптировать под ваш проект.
